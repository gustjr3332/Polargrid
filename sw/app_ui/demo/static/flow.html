How one command travels (latest command, zone -)

1Controller (MEC app) creates one CIN in ctl/grp/fopt of the zone's MN
2The GRP fans it out: a command CIN appears in every cell's command container (we watch cell 0)
3Each cell AE reads its angle and updates its state FlexContainer (opeLl, 0 closed .. 100 open)
4Desk sensors report new lux in env/desks with the same command id: the window moved, the desk light changed
Step 1 is inferred from step 2 (we cannot see the request itself, only its result). Times are when this page first saw each step (CINs polled every 1 s, other cells' states every few seconds), so they are coarse and are not latency measurements. In this setup the controller calls the MN directly over HTTP; the IN holds the registration of each MN (MQTT lines between IN and MNs).
